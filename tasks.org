* DONE Trim template-workflow overkill for this solo project

Disabled the token-heavy and noise-heavy parts of the rust-template workflow
that do not earn their keep on a private, unreleased, solo game:

- *Per-turn template-compliance review gate* — unwired the Stop hook in
  =.claude/settings.json= (the =review-stop.sh= script and the
  =template-compliance= agent stay in the repo).  This was the main Claude-token
  sink: it spawned a reviewing subagent on every turn that touched code.
- *Dependabot version updates* — removed =.github/dependabot.yml= to stop
  automated dependency PRs.  The now-inert automerge workflow is left in place.
- *Local =cargo-semver-checks=* — dropped from the flake dev shell; it is ABI
  stability tooling for published libraries, and this project is not published.

Kept: the Nix dev shell, =treefmt=, local tests, the structural compliance
checker (=just compliance=, which is cheap and not per-turn), CI, the Elm
frontend, and the server-crate stub.

Each deviation is recorded as a =compliance-ignores= entry in
=rust-template.json=.  Re-enable any one by reverting its change and removing
the matching ignore.

* TODO Browser-based map editor for the empire-builder game board

Full design and feature outline: =docs/map-editor-design.org=.  The editor moves
from the terminal into the browser — an Elm SPA renders a large, scrollable
ASCII map and the server (later) persists maps — because the project targets a
web game and a terminal window is too cramped for large, complex boards.  Elm
builds offline with only core packages, so this needs no new dependencies.

Phases (see the design doc for the full feature list):

1. [DONE] Model and palette — a rich, data-driven terrain palette in
   =data/terrain.toml=; the =first-food-cli palette= command emits it as JSON
   for the front end.
2. [IN PROGRESS] Editor v1 (Elm) — load the palette, render a scrollable colored
   grid with a movable viewport over large maps, a terrain palette, paint /
   bucket-fill / eyedropper tools, new map, undo/redo, save/load JSON, and a
   status bar.  Served as static files via =just editor=.
3. [TODO] Server API — the server serves the SPA and persists maps (get/save/
   list) so boards live on the server, not only as downloads.
4. [TODO] Navigation and tools — zoom, minimap, brush size, resize/crop.
5. [TODO] Accounts and local save — per-user maps behind login; local save.
6. [TODO] Layers and generation — features, resources, rivers; procedural
   landmass/climate generation.
